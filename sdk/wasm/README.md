# curs3d-wallet-wasm

Browser-side crypto bundle for CURS3D — generates keypairs, signs transactions,
encrypts wallets — entirely inside the browser, with no plaintext private key
ever leaving the page.

## What's inside

| Primitive | Crate | Notes |
|-----------|-------|-------|
| Post-quantum signatures | `ml-dsa` (RustCrypto) | FIPS-204 ML-DSA-87, NIST level 5 |
| KDF | `argon2` | Argon2id, m=64 MiB, t=3, p=4 — same as the node CLI |
| Wallet encryption | `aes-gcm` | AES-256-GCM, 12-byte nonce, 16-byte salt |
| Hashing | `sha3` | SHA-3-256 + EIP-55 mixed-case checksum |

## Interop with the CURS3D node

Both this crate and the node depend on the **same** `ml-dsa = =0.1.0-rc.9`
(RustCrypto, FIPS-204 ML-DSA-87, pure Rust). A signature produced in the
browser is byte-for-byte verifiable by `core::transaction::Transaction::
verify_signature` on the node — `/api/tx/submit` accepts wallet-signed
transactions starting with **protocol v5** (the migration hardfork).

Sizes (FIPS-204 NIST level 5):

| Field | Bytes |
|-------|-------|
| Public key (verifying key) | 2592 |
| Secret key (we store the 32-byte seed and re-derive on demand) | 32 |
| Signature | 4627 |

The historical pre-v5 node used `pqcrypto-dilithium 0.5.0` (NIST round 3);
that path is gone — see `CLAUDE.md` "Hardfork procedure (v4 → v5)".

## Build

```bash
# From the repo root:
rustup target add wasm32-unknown-unknown   # one-off
cd sdk/wasm

# Plain cargo build, exercises the same toolchain wasm-pack uses internally:
cargo build --target wasm32-unknown-unknown --release

# Bundle for the browser (ES modules + .d.ts in pkg/):
cargo install wasm-pack            # one-off
wasm-pack build --target web --release
```

Output:

```
sdk/wasm/pkg/
├── curs3d_wallet_wasm.js          ES module loader
├── curs3d_wallet_wasm_bg.wasm     binary (this is the size to budget)
├── curs3d_wallet_wasm.d.ts        TypeScript types
└── package.json
```

`pkg/` is gitignored — it's regenerated by `wasm-pack`.

### Size

`opt-level = "z" + lto + codegen-units = 1 + panic = abort + strip` keeps the
release `.wasm` lean. As deployed today
(`https://curs3d.fr/wallet-wasm/curs3d_wallet_wasm_bg.wasm`):

| Artifact | Size |
|----------|------|
| `curs3d_wallet_wasm.js` (ES module shim) | ~24 KB |
| `curs3d_wallet_wasm_bg.wasm` (no `wasm-opt`) | ~236 KB |

`wasm-opt` (binaryen) was missing on the build host so the WASM is
unoptimised; with `wasm-opt -Oz` the bundle drops to ~100 KB. To enable:
`brew install binaryen` (macOS) or `apt install binaryen`. To suppress the
warning instead, set
`wasm-opt = false` under
`[package.metadata.wasm-pack.profile.release]` in `Cargo.toml`.

## API (TypeScript-ish)

```ts
class KeyPair {
  static generate(): KeyPair
  address(): string                                    // "CUR..." (EIP-55)
  publicKeyHex(): string                               // hex-encoded
  sign(message: Uint8Array): string                    // hex signature
  saveEncrypted(password: string): string              // JSON blob
  static loadEncrypted(json: string, password: string): KeyPair
}

function verifySignature(
  publicKeyHex: string,
  message: Uint8Array,
  signatureHex: string,
): boolean

function buildTransferTx(
  keypair: KeyPair,
  toAddress: string,         // "CUR..." or 0x...
  amountMicrotokens: bigint, // u64
  feeMicrotokens: bigint,    // u64
  nonce: bigint,             // u64
): string                    // JSON ready for POST /api/tx/submit

function buildTransferTxAdvanced(
  keypair: KeyPair,
  toAddress: string,
  amountMicrotokens: bigint,
  feeMicrotokens: bigint,
  nonce: bigint,
  timestamp: bigint,         // i64 unix seconds (deterministic for tests)
  chainId: string,
): string
```

### EncryptedWallet JSON shape

The same shape as the node's `wallet::EncryptedWallet`, so wallet files are
interchangeable between the CLI and the browser:

```json
{
  "salt": "<32 hex chars = 16 bytes>",
  "nonce": "<24 hex chars = 12 bytes>",
  "ciphertext": "<hex>",
  "version": 1
}
```

KDF: Argon2id, `m_cost = 65_536` KiB (64 MiB), `t_cost = 3`, `p_cost = 4`,
output 32 bytes. The 32-byte key is consumed directly by AES-256-GCM with a
12-byte nonce.

### Transaction JSON shape

`buildTransferTx` returns a JSON object whose field set mirrors the node's
`core::transaction::Transaction` struct. The signature is computed over

```
b"curs3d-tx-v1:" || bincode(SignableTransaction { ... })
```

with the field order

```rust
chain_id, kind, from, sender_public_key, to,
amount, fee, max_fee_per_gas, max_priority_fee_per_gas,
nonce, timestamp, gas_limit, data
```

Both sides speak FIPS-204 ML-DSA-87 (same crate, same version), so the
node's `verify_signature` accepts the result directly.

## Tests

```bash
cd sdk/wasm
cargo test
```

The tests are pure-Rust (native), not `wasm-bindgen-test`, so no headless
browser runner is needed. They cover:

1. Keygen / sign / verify roundtrip.
2. Verify rejects tampered messages.
3. Verify rejects signatures from a different keypair.
4. EIP-55 mixed-case checksum on every generated address.
5. Address determinism (same pubkey → same address; round-trip via
   `from_bytes`).
6. Encrypted wallet save → load roundtrip.
7. Wrong-password rejection on encrypted wallet.
8. EncryptedWallet JSON shape (salt 16 B, nonce 12 B, version=1).
9. End-to-end Transfer tx: build → re-parse the JSON → recompute the canonical
   signable bytes → re-verify the embedded signature with the same code path
   the node uses.
10. Address-form parser accepts `CUR…`, `0x…`, and bare hex.
11. Address-form parser rejects malformed input.
12. ML-DSA-87 sizes match the FIPS-204 NIST L5 spec
    (PK = 2592 B, signature = 4627 B).

## Crate is excluded from the root workspace

`sdk/wasm` is a standalone crate. The CURS3D root has no top-level
`[workspace]` table, so this crate is automatically out-of-tree — running
`cargo build` at the repo root won't try to build it for the host target.
This is intentional: `cargo build --target wasm32-unknown-unknown` is the
only configuration in which this crate makes sense.
